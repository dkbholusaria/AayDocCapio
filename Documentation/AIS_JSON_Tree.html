Common Data Format & Validation Rules

These patterns define the structural and formatting constraints applied to input columns by validationRegex in the JSON schemas.

Validation TypeRegex PatternDescription & Expected Format
Security Name & Code ^[A-Za-z0-9][A-Za-z0-9*!'\" :()_@./#&+%\-,]{0,219}[(][A-Z0-9]{12}[)]$ Requires the format: Security Name (Security Code). E.g., ABC Fund (IBF201K01222). Code must be a 12-character alphanumeric ISIN.
Name & PAN Format ^[A-Za-z][A-Za-z#:,/.'()\s-&]{0,149}[(][A-Z]{5}[0-9]{4}[A-Z]{1}[)]$ Requires the format: Assessee/Party Name (PAN). E.g., Dipak Singh (AABPS1213C). PAN must follow the standard 10-character alphanumeric format.
Financial Amounts ^(?=.*[1-9])\d{1,14}(?:\.\d{1,2})?$
or ^\d{1,14}((\.\d{1,2})?)$		 Non-negative decimal values. Up to 14 integer digits, with up to 2 decimal places. E.g., 15000.50.
Integers / Counts ^\d+$ or ^[0-9]{1,14}$ Standard non-negative integer digits. Used for counts, quantities, or round/integer amounts.
Holder Constraint ^[0-3]$ Limits the number of joint holders to a maximum of 3.
Accounts / Refs ^0{0,30}[1-9a-zA-Z][0-9a-zA-Z/]{3,120}$ Validation format for bank accounts, deposits, or registration reference numbers. E.g. no leading zeroes or blank spaces.
